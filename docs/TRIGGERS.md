# تریگرها و اتوماسیون (Automation Triggers)

صفحه‌ی `#/triggers` در داشبورد، لایه‌ی اتوماسیون دیبا پل است: هر «تریگر» یک
**رویداد (When)** و یک **اقدام (Then)** دارد و می‌تواند پیام‌رسان‌ها، هوش مصنوعی
دیبا روتر، ابزارهای MCP و سرویس‌های بیرونی را به هم وصل کند.

## رویدادها

| رویداد | توضیح | متغیرهای قابل استفاده |
|---|---|---|
| `incoming_message` | پیام ورودی در یکی از سرویس‌ها (بله، ایتا، روبیکا، سروش، تلگرام، واتس‌اپ، اینستاگرام، ایکس، لینکدین) | `{{sender}}` `{{username}}` `{{text}}` `{{provider}}` `{{chatId}}` `{{chatTitle}}` |
| `tool_called` | فراخوانی موفق یک ابزار MCP (از مدل یا داشبورد) | `{{toolName}}` `{{args}}` `{{ms}}` |
| `tool_error` | خطای یک ابزار MCP | `{{toolName}}` `{{error}}` `{{args}}` |

## اقدام‌ها

| اقدام | کار |
|---|---|
| `reply_template` | ارسال متن آماده به همان چت (با متغیرها) |
| `ai_reply` | دریافت پاسخ از دیبا روتر با System Prompt دلخواه و ارسال آن |
| `forward` | ارسال پیام به سرویس/چت مقصد (همگام‌سازی بین پیام‌رسان‌ها) |
| `call_tool` | اجرای هر ابزار MCP با آرگومان JSON (با جایگزینی متغیرها) |
| `webhook` | `POST` کردن JSON رویداد به آدرس بیرونی (n8n، Make، CRM، Google Sheets، Slack) |

## شرط‌ها (match)

```json
{ "provider": "*", "chatType": "private", "contains": "قیمت, تعرفه, خرید", "toolName": "*" }
```

- `provider`: `*` یا شناسه‌ی سرویس مثل `bale_client`، `telegram_client`، `instagram`.
- `chatType`: `*` / `private` / `group` / `channel`.
- `contains`: فهرست کلمات با کاما؛ هر کلمه می‌تواند الگوی `*` داشته باشد. خالی = همه‌ی پیام‌ها.
- `toolName`: برای رویدادهای ابزار؛ مثلاً `*_send_*` یا `*_publish_*`.

## کتابخانه‌ی نمونه

نصب تازه ۳۸ نمونه‌ی آماده در `data/triggers.json` می‌سازد (۱۱ پیام‌رسان، ۸ هوش
مصنوعی، ۸ فوروارد، ۶ MCP، ۵ وبهوک) و ۲۰ گزارش اجرای نمونه برای پیش‌نمایش تاریخچه.
همه‌ی نمونه‌ها **خاموش** شروع می‌شوند تا هیچ پیامی بدون تصمیم شما ارسال نشود.

با بالارفتن `seedVersion` در `src/core/triggers.ts`، نمونه‌های تازه به نصب‌های
موجود اضافه می‌شوند؛ تریگرهای سفارشی و ویرایش‌شده‌ی شما دست‌نخورده می‌مانند.
دکمه‌ی «بازنشانی پیش‌فرض‌ها» هم نمونه‌های جامانده را برمی‌گرداند.

## API

| متد و مسیر | کار |
|---|---|
| `GET /api/triggers` | `{ triggers, logs, seedVersion }` |
| `POST /api/triggers` | ساخت تریگر جدید |
| `PUT /api/triggers/:id` | ویرایش (مثلاً `{ "enabled": true }`) |
| `DELETE /api/triggers/:id` | حذف |
| `POST /api/triggers/:id/test` | اجرای آزمایشی و ثبت گزارش |
| `POST /api/triggers/reset-defaults` | بازگرداندن نمونه‌های جامانده |
| `DELETE /api/triggers/logs` | پاک کردن گزارش‌ها |

همه‌ی مسیرها نیاز به نشست واردشده دارند (`GET /api/triggers` بدون ورود = `401`).

## چند سناریوی آماده

- **پشتیبانی ۲۴ ساعته:** `social-welcome` + `social-support-ticket` + `ai-private-qa`
  را روشن کنید تا سلام و سوال‌ها خودکار و کوتاه پاسخ بگیرند.
- **پل بین پیام‌رسان‌ها:** `bridge-bale-to-telegram` و `bridge-telegram-to-bale` را
  روشن کنید (چت پیش‌فرض هر سرویس باید تنظیم شده باشد).
- **اتوماسیون نود‌رِد:** `webhook-incoming-all` را روشن و آدرس n8n را وارد کنید؛
  بدنه‌ی ارسالی شامل `event`، `trigger`، `vars` و `message` است.
- **مانیتورینگ:** `mcp-tool-error-alert` یا `mcp-tool-error-webhook` را روشن کنید
  تا خطاهای ابزارها فوراً به مدیر یا Grafana برسد.

## نکته‌ی امنیتی

اقدام‌های `call_tool` و `webhook` می‌توانند داده به بیرون بفرستند؛ مقصد را با دقت
انتخاب کنید و برای تست از دکمه‌ی «تست اجرا» استفاده کنید. تریگرها با داده‌ی
واقعی یک چت فقط زمانی اجرا می‌شوند که واقعاً روشن باشند.
